## 三、项目简介（限 400 字）

本项目用 Rust 从零实现了一个面向移动设备的 LaTeX 数学排版引擎，约 2900 行代码、68 个单元测试，只处理数学模式：输入公式字符串，输出扁平绘制指令，包括每个字形的码位、坐标与缩放，以及分数线和根号横线的矩形。渲染层照指令绘制即可，不需要理解 TeX。

动机来自实际问题：Android 上常用的 jlatexmath 是 GPL-2.0 许可，接入后整个应用会被传染为 GPL 派生作品；它还依赖 JVM，体积与启动开销大。本引擎只依赖一个字体解析库，可编译为静态库或动态库嵌入任意宿主。

方法上，手写词法分析器与递归下降解析器构建语法树，按 TeX 的 Box 模型做基线对齐布局，并通过 OpenType 的 MATH 表读取字体度量常量，目前支持分式、根式、上下标、大运算符、矩阵与字体族等约 270 个命令。

验证方面，与 jlatexmath 在同一组公式上对比，本引擎布局耗时中位数 3.2 微秒，矩阵类快约 5 倍；59 条真实文档公式与 20 条教材公式全部渲染成功，无命令丢失、无缺字。通过字形轮廓缓存，20×20 矩阵渲染从 18 毫秒降到 2.8 毫秒。

> 字数约 390（含标点）。填表前用记事本字数统计核一遍。

## 五、查新报告要点

### 5.1 查新项目名称

面向移动设备的轻量级 LaTeX 数学排版引擎

### 5.2 创新要点（填「二．查新项目的创新要点」）

1. **纯 Rust 实现、无 JVM 依赖**：现有 Android 端方案 jlatexmath 依赖 Java 运行时；KaTeX 与 MathJax 需要 WebView 或 JS 引擎；两者在手表、嵌入式这类小内存设备上都不合适。本引擎只依赖一个字体解析库，可编成单一动态库。
2. **以 OpenType MATH 表常量驱动布局**：上下标位移、根号间隙、分数线粗细等几何参数不是硬编码经验值，而是按字体自带的 MATH 表读取，换字体时布局规则随之适配。
3. **宽容解析与可诊断性**：未知命令不会让整条公式解析失败，而是按字面降级渲染，同时向宿主回报「哪些命令没被支持」的清单。聊天、笔记这类用户手打公式的场景里，整段公式消失比显示得难看糟糕得多。
4. **许可合规的替代路径**：以自研实现替换 GPL 许可的既有库，规避了在闭源或商用应用中的许可传染问题。

### 5.3 查新点（填「三．查新点」）

移动端、无 JVM/WebView 依赖、基于 MATH 表常量的 TeX Box 数学排版引擎。

### 5.4 检索词与策略（填「四．文献检索范围及检索策略」）

| 组 | 检索词 |
|---|---|
| 1 | LaTeX 排版引擎 / math typesetting engine / TeX layout |
| 2 | 移动端 / Android / embedded / Rust |
| 3 | OpenType MATH table / 数学字体度量 |
| 4 | jlatexmath / KaTeX / MathJax |

组合方式：`1 AND 2 AND 3`、`1 AND 4`。

检索库建议：中国知网、万方、维普、中国专利信息网、IEEE Xplore、GitHub 关键词检索，年限 2010 至今。

### 5.5 查新结论（填「六．查新结论」）

经检索，国内外已有 LaTeX 数学排版引擎的公开报道，但形态集中在两类：一是基于 JVM 的实现（jlatexmath），二是基于浏览器的实现（KaTeX、MathJax）。同时检索到若干 Rust 写的排版与数学库，但未见与本项目相同的报道，即：**以纯 Rust 实现、不依赖 JVM 与浏览器运行时、以 OpenType MATH 表常量驱动布局、面向移动设备并带宽容解析与不支持命令回报机制**的数学排版引擎。本项目的查新点在检索范围内具有新颖性。

> 结论要写「未见相同报道」，不要写「国际领先」这类无法证明的话。
